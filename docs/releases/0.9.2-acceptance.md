## Release decision and scope

`0.9.2` is a core-maintenance patch within the frozen `0.9.x` candidate
contract. Its two implementation changes are:

- `2b17d28`: include locales installed only through catalog chunks in
  `I18n::translator_from_code` negotiation. Normalization, parent lookup,
  configured fallback, and the generated facade's configured-locale policy
  remain unchanged.
- `4bde93b`: enforce the existing 65,536-byte MF2 text-output limit before
  accumulating each text or formatted-expression contribution, including
  bidi controls. Overflow stops the remaining pattern, retains errors
  already discovered, and returns the bounded whole-message fallback.
  Skipped tail expressions produce no further handler calls or errors.

The preceding maintenance record documents regression failures against the
original locale implementation and output-boundary cases, including
multibyte text, cross-part surrogate pairs, fallback bounds, and error order.
See [the pre-release maintenance record](unreleased-core-fixes-2026-09-18.md)
for that historical evidence; its earlier consumer revisions and toolchain
observations are not restated as current Registry acceptance.

There is no change to public MoonBit interfaces, the generated-facade API or
template, authoring profiles, catalog or manifest formats, CLI commands,
diagnostic codes, wire contracts, supported targets, or Node/browser host
policy. The `0.9.0` candidate snapshot remains frozen.

The roadmap policy recorded in `cba1a6e` keeps development on `0.x` until
MoonBit officially releases `1.0`. That upstream release is a prerequisite
for considering this library's `1.0.0`, not an automatic promotion or a
replacement for its independent compatibility, conformance, and consumer
gates.

## Contract scope and retained limitations

Stable authoring remains `unicode-mf2-ldml48.2-js-v2`, pinned to Unicode
MessageFormat WG LDML 48.2 commit
`7f142fb4f1f5ea6ab1eb34ce2b87e918ca9fd331`. The stable JavaScript claim
continues to cover six stable functions and 40 stable options. Draft
date/time requires the separate
`unicode-mf2-ldml48.2-js-v2+experimental-datetime-v1` profile; Draft `:unit`
remains deferred, custom functions are extensions, and Native/Wasm do not
ship a project-owned CLDR formatter.

The output fix bounds core text accumulation. Allocations already made by
callers, custom-handler internal work, and aggregate structured metadata
remain outside that guarantee. Declaration resolution and pattern selection
still precede pattern formatting. It does not establish a new aggregate byte
limit for options, attributes, or formatter fields.

The maintained example's application-owned catalog loader remains a narrow,
same-origin text adapter without an independent timeout or response-body
size cap. Integrity metadata is checked before installation; the adapter is
excluded from the published library archive. Toolchain modernization and
loader hardening remain separate maintenance work.
