## Application-owned catalog loading

Each catalog request has a 10-second deadline covering headers and body.
Streaming reads count actual bytes, require the generated metadata's exact
byte length, and enforce a 65,536-byte ceiling. Strict UTF-8 decoding handles
split multibyte sequences and preserves an initial BOM for integrity checking.
The application verifies the existing SHA-256 metadata before installation.

Failures abort the request and cancel its stream. The current locale stays
active until all required chunks validate; retry fetches only missing chunks.
Attempt IDs reject callbacks from older attempts, including a retry for the
same locale. This adapter remains example application code outside the
published library.

Six new browser scenarios cover stalled headers, stalled bodies, oversized
streaming responses with misleading Content-Length, invalid UTF-8 and
same-length payload tampering, byte-by-byte UTF-8 delivery and cleared timers,
and stale callbacks during retry. Existing application and MF2 browser
scenarios remain included.

## Release workflow and remaining acceptance

Registry smoke is now manually dispatched with exact version, full source
SHA, and archive SHA-256. It verifies the checked-out revision and version,
then compares the downloaded archive against both registry metadata and the
supplied checksum before executing the consumer smoke. It no longer depends
on tags. The historical publish-client exit-255 exception is restricted to
the two documented old toolchain/client pairs; the current baseline requires
successful exit status.

Remote Test CI, macOS/Windows execution, publish dry run, real publication,
and exact `0.9.3` Registry smoke have not been run. Prior `0.9.2` Registry or
Bingque acceptance is historical evidence and is not counted as new `0.9.3`
