## Release decision and upgrade scope

This is a compatibility-maintenance patch release rather than `0.10.0`.
There is no change to a public MoonBit interface, generated-facade API or
template, authoring profile, catalog or manifest format, CLI command surface,
diagnostic or wire contract, supported target set, or Node/browser host
policy. The `0.9.0` candidate snapshot remains frozen; `0.9.1` advances its
exact supported build baseline to archive `0.10.9+6e6c44045` (Moon
`0.1.20260819`, moonc `0.10.9`) and compatible implementation dependencies.

The direct MoonBit pins are `moonbitlang/x@0.5.1`,
`moonbitlang/parser@0.3.18`, and `moonbitlang/async@0.21.0`; the other direct
pins remain current. CI uses `actions/setup-node@v7.0.0` by full commit SHA.
The maintained browser example uses Rabbita `0.15.4`, Warren `0.3.2`, and a
repository-local Terser `5.50.0` pin. The installer hashes and Node.js 26.7.0
host pin remain unchanged after online verification.

## MF2 and contract scope accepted

`0.9.1` preserves the JavaScript Unicode MF2 conformance candidate frozen in
`0.9.0`; it does not make a broader conformance claim. The stable authoring
profile remains `unicode-mf2-ldml48.2-js-v2`. Draft date/time behavior remains
available only through explicit
`unicode-mf2-ldml48.2-js-v2+experimental-datetime-v1` opt-in.

Conformance remains pinned to the Unicode MessageFormat Working Group LDML
48.2 tag at commit `7f142fb4f1f5ea6ab1eb34ce2b87e918ca9fd331`. The
normative matrix contains 77 anchored rows, 40 stable options, six stable
functions, and zero blockers. The independent differential set contains 24
cases with zero unexplained failures. The real-browser harness executes the
pinned syntax/data-model, resolution, function, and differential suites in
each browser engine.

`docs/contracts/1.0-candidate.json` continues to freeze the public interface
hashes, generator template, profile and wire contracts, CLI surface,
diagnostics, and support policy. The three-consumer exact-version gate remains
the historical `0.9.0` candidate evidence and is not restated as a `0.9.1`
consumer migration.

## Accepted limitations

The stable MF2 claim remains limited to the JavaScript profile. Draft
date/time is experimental, Draft `:unit` remains deferred, custom functions
are extensions, and Native/Wasm do not ship a project-owned CLDR formatter.

The maintained browser bundle has only 3516 raw bytes (about 3.4 KiB) of
headroom. Future compiler or framework upgrades must continue to pass the
size gate. The example's application-owned catalog loader is intentionally a
narrow, same-origin, text-only adapter; it has no independent timeout or body
size cap. Downloaded catalog content is still checked against the generated
integrity metadata before installation, and this example adapter is excluded
from the published library archive.
