## Manual product review

1. Open the Mooncakes link above and confirm the README is readable, metadata
   is correct, roadmap/profile links open, and the `runtime`, `runtime/js`,
   and `generator` API pages are useful. Confirm the README shows the pinned
   `moonx lampclaw/i18n/cmd/i18n@0.1.0-rc.3` workflow; the executable package
   has no public API page to review.
2. Run the repository example and verify the visible flow:

   ~~~bash
   cd examples/rabbita_todo
   moon update
   moon install moonbit-community/warren@0.2.2
   warren dev
   ~~~

   Add and complete a todo, switch to Chinese, refresh and confirm Chinese is
   restored after its catalog loads, then switch to English, refresh and
   confirm English remains active. In browser DevTools, confirm `zh-CN.json`
   is requested only once within each application lifetime. A refresh creates
   a new in-memory catalog registry, although the HTTP cache may avoid another
   transfer. Todo items are not expected to survive a refresh.
3. Optionally review one real consumer (`lampclaw-com`, `bingque-com`, or
   `apexlsai_com`) to confirm its existing language experience is unchanged.
4. Confirm the documented product boundary is acceptable: `0.1.0` is the
   frozen Web/JavaScript strict-v1 baseline, not full Unicode MF2 conformance;
   examples are source-repository assets and are not inside the Mooncakes
   archive.

## Known non-blocking boundaries

- The current MF2 behavior is
  `lampclaw-mf2-strict-v1+lampclaw-datetime-v1`, a documented subset.
- Locale-sensitive formatter conformance is supported on JavaScript; other
  MoonBit backends provide the portable core and limited formatting.
- Library consumers resolve the single module's authoring dependencies even
  when they use only runtime packages; reachability prevents them from being
  linked into the application artifact.
- Mooncakes' generated `rc.3` API index omits the executable-only `cmd/i18n`
  leaf even though it is present in the source archive and exact-version
  `moonx` plus `moon add --bin` both pass. Runtime, generator, and JavaScript
  formatter API pages render normally; CLI delivery is verified by execution.
- The pinned publish client may exit 255 after a successful dry run. The real
  `rc.3` publish exited 0; the precise handling rule remains documented.

## Decision

**Approved for stable promotion.** The owner reported that validation passed
and requested publication of `0.1.0`. Any failure discovered before the real
publish stops the release; the existing `v0.1.0-rc.3` tag remains immutable.
