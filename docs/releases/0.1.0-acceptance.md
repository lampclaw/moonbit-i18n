## Manual product review

1. Open the Mooncakes link above and confirm the README is readable, metadata
   is correct, roadmap/profile links open, and the `runtime`, `runtime/js`,
   `generator`, and `cmd/i18n` API pages are useful.
2. Run the repository example and verify the visible flow:

   ~~~bash
   cd examples/rabbita_todo
   moon update
   moon install moonbit-community/warren@0.2.2
   warren dev
   ~~~

   Add and complete a todo, switch to Chinese, switch back to English, and
   confirm the language change and todo state feel correct. In browser DevTools,
   confirm `zh-CN.json` is requested only on first use.
3. Optionally review one real consumer (`lampclaw-com`, `bingque-com`, or
   `apexlsai_com`) to confirm its existing language experience is unchanged.
4. Confirm the documented product boundary is acceptable: `0.1.0` is the
   frozen Web/JavaScript strict-v1 baseline, not full Unicode MF2 conformance;
   examples are source-repository assets and are not inside the Mooncakes
   archive.

## Known non-blocking boundaries

- The current MF2 behavior is
  `lampclaw-mf2-strict-v1+lampclaw-datetime-v1`, a documented subset.
- Locale-sensitive formatter conformance is supported on JavaScript; other
  MoonBit backends provide the portable core and limited formatting.
- Library consumers resolve the single module's authoring dependencies even
  when they use only runtime packages; reachability prevents them from being
  linked into the application artifact.
- The pinned publish client may exit 255 after a successful dry run. The real
  `rc.2` publish exited 0; the precise handling rule remains documented.

## Decision

Reply with explicit approval only after the manual product review. The next
release task will then set the version to `0.1.0`, update the changelog and
active documentation references, rerun all frozen gates, publish once, repeat
the registry and consumer smokes, and record final evidence.

If any review item fails, record the observed page/action, browser or command,
and actual result. Fix it in a new `0.1.0-rc.N`; do not move or replace the
existing `v0.1.0-rc.2` tag.
